# M2 실계정 검증 절차

- 목적: `sync`/`resolve`를 **실제 Dooray 계정**에서 한 번 돌려 보고 M2 완료를 선언할 근거를 만든다.
- 전제: 자동 테스트 71건은 전부 통과했지만 **실제 API로는 1바이트도 보낸 적이 없다.**
  M1에서 코드 리뷰가 못 잡고 실계정이 잡은 것이 있었다(전송 계층 오류, 폴더당 0.4초 — 운영교훈 §8).

## 0. 안전 원칙 (이걸 어기면 나머지는 의미 없다)

| 원칙 | 이유 |
|---|---|
| **파일럿 프로파일(`work` 등)에 `sync`를 쓰지 않는다.** 시험용 프로파일을 새로 만든다 | M2는 실계정 미검증이다. 검증되지 않은 코드로 실데이터를 만지지 않는다 |
| 설정·상태 DB를 `.dbg` 아래로 **격리**한다 | 시험이 실제 프로파일의 기준선을 건드리는 사고를 원천 차단(운영교훈 §16) |
| 원격도 **새 폴더**를 쓴다(`_m2_test`) | 기존 폴더에 시험 파일이 섞이면 되돌리기가 수작업이다 |
| 삭제 전파(`--propagate-deletes`)는 **이 시험 폴더에서만** 쓴다 | 되돌리기 어려운 유일한 동작 |
| 각 단계에서 `--dry-run`을 먼저 보고 숫자를 확인한 뒤 실행한다 | 운영교훈 §15 |

## 1. 준비 (한 번만)

**PowerShell 새 창**을 열고 아래를 그대로 실행한다. 환경변수는 이 창에서만 유효하므로,
검증이 끝나면 **창을 닫는 것만으로** 원래 설정으로 돌아간다.

```powershell
cd C:\drive\dev\dooraydrive
git checkout m2-bidirectional
$env:DOORAY_SYNC_CONFIG_DIR = "C:\drive\dev\dooraydrive\.dbg\m2\cfg"
$env:DOORAY_SYNC_STATE_DIR  = "C:\drive\dev\dooraydrive\.dbg\m2\state"
New-Item -ItemType Directory -Force "C:\drive\dev\dooraydrive\.dbg\m2\local" | Out-Null
```

격리가 실제로 걸렸는지 먼저 확인한다. **여기서 경로가 `.dbg\m2` 아래가 아니면 중단하라.**

```powershell
python diag.py
```

토큰은 keyring에 이미 있으므로 그대로 쓰인다(설정 경로만 격리된 것이다).

## 2. 초기화 — 원격에 시험용 폴더를 만든다

```powershell
python -m dooray_sync.cli.main init -p m2test --drive-id (드라이브id) --local-root "C:\drive\dev\dooraydrive\.dbg\m2\local" --remote-path "_m2_test" --create-remote
```

드라이브 id를 모르면 `--drive-id`를 빼고 실행하면 목록에서 고를 수 있다.

**확인**: `원격 폴더 생성: _m2_test` 가 뜨고 `기록 0건`으로 끝나면 정상이다.

## 3. 1패스 — 양방향이 맞물리는가

로컬에 파일을 몇 개 만든다.

```powershell
"로컬에서 만든 파일" | Out-File -Encoding utf8 "C:\drive\dev\dooraydrive\.dbg\m2\local\로컬.txt"
New-Item -ItemType Directory -Force "C:\drive\dev\dooraydrive\.dbg\m2\local\하위" | Out-Null
"하위 파일" | Out-File -Encoding utf8 "C:\drive\dev\dooraydrive\.dbg\m2\local\하위\a.txt"
```

Dooray 웹에서 `_m2_test` 폴더에 파일 하나를 **직접 업로드**한다(이름 예: `원격.txt`).

```powershell
python -m dooray_sync.cli.main sync -p m2test --full --dry-run
```

**확인할 것**
- 동작별 건수 표에 `신규업로드 2` / `원격폴더생성 1` / `신규받기 1` 정도가 뜨는가
- **`실제로 사라질 항목: 0건`** — 여기가 0이 아니면 즉시 중단하고 알려 달라

숫자가 맞으면 실행한다.

```powershell
python -m dooray_sync.cli.main sync -p m2test --full
```

## 4. 2패스 — 가장 중요한 단계

바로 다시 실행한다.

```powershell
python -m dooray_sync.cli.main sync -p m2test
```

**기대: `변경 없음`.** 여기서 무언가 다시 올라가거나 `보호`가 뜨면 그게 결함이다.

> 이 단계가 중요한 이유: 이번 검증에서 나온 critical 결함(업로드된 파일의 기준선이 비어
> 다음 실행부터 영원히 보류됨)이 정확히 여기서만 드러났다. 테스트 52건이 전부 통과하는
> 상태였다(운영교훈 §23).

## 5. 원격 → 로컬 반영

> **주의 (2026-08-03 실측)**: Dooray 웹에는 txt 편집기가 없다. "웹에서 파일을 고친다"가
> 안 되므로, **로컬 파일을 고쳐서 올리면 양쪽이 같은 내용이 되어 이 단계가 성립하지 않는다.**
> 원격만 바뀐 상태를 만들려면 **동기화 폴더 밖에서** 사본을 고쳐 올려야 한다.

```powershell
# 동기화 폴더 '밖'에 사본을 만들어 고친 뒤, 그것을 웹에서 같은 이름으로 업로드한다
Copy-Item "C:\drive\dev\dooraydrive\.dbg\m2\local\원격.txt" "$env:TEMP\원격.txt"
"원격에서만 추가된 줄" | Out-File -Encoding utf8 -Append "$env:TEMP\원격.txt"
explorer $env:TEMP        # 이 파일을 Dooray 웹의 _m2_test 에 같은 이름으로 업로드
```

로컬 `.dbg\m2\local\원격.txt`는 **건드리지 않는다** — 그래야 '원격만 변경'이 된다.

```powershell
python -m dooray_sync.cli.main sync -p m2test --dry-run
python -m dooray_sync.cli.main sync -p m2test
Get-Content "C:\drive\dev\dooraydrive\.dbg\m2\local\원격.txt"
```

**기대**: `갱신받기 1건`, 로컬 내용이 웹에서 고친 내용과 같다.

## 6. 로컬 → 원격 반영

```powershell
"로컬에서 고침" | Out-File -Encoding utf8 -Append "C:\drive\dev\dooraydrive\.dbg\m2\local\로컬.txt"
python -m dooray_sync.cli.main sync -p m2test
```

**기대**: `새버전업로드 1건`. 웹에서 내용이 바뀌었는지 확인.

## 7. 충돌 — 양쪽 보존이 실제로 되는가

**같은 파일을 양쪽에서 서로 다르게** 고친다. 순서가 중요하다.

1. Dooray 웹에서 `로컬.txt`를 수정한다 (예: 끝에 `원격측 수정` 추가)
2. 곧바로 로컬에서도 수정한다

```powershell
"로컬측 수정" | Out-File -Encoding utf8 -Append "C:\drive\dev\dooraydrive\.dbg\m2\local\로컬.txt"
python -m dooray_sync.cli.main sync -p m2test --dry-run
python -m dooray_sync.cli.main sync -p m2test
dir "C:\drive\dev\dooraydrive\.dbg\m2\local"
```

**확인할 것 (M2 완료 기준의 핵심)**
- `충돌보존 1건`이 뜬다
- `로컬.txt (충돌 2026-.. ....).txt` 파일이 생겼고 **내 수정 내용이 그대로 있다**
- `로컬.txt`에는 **원격 내용**이 들어 있다
- **어느 쪽 내용도 사라지지 않았다** ← 이게 유실 0건의 실증이다

```powershell
python -m dooray_sync.cli.main resolve -p m2test --list
python -m dooray_sync.cli.main resolve -p m2test --id 1 --keep both
```

`--keep local`도 시험해 보려면 충돌을 한 번 더 만든 뒤 그 쪽을 고르고,
**다음 `sync`에서 그 파일이 실제로 업로드되는지** 확인한다(여기서 결함이 하나 있었다).

## 8. 폴더 개명 — 대량 오삭제가 없는가 (R8/B4)

Dooray 웹에서 `_m2_test/하위` 폴더 이름을 `하위2`로 바꾼다.

```powershell
python -m dooray_sync.cli.main sync -p m2test --dry-run
```

**확인할 것**
- **`실제로 사라질 항목: 0건`** ← 폴더 개명이 삭제로 오인되지 않는다는 실증
- `로컬이동` 또는 `로컬폴더생성`이 뜬다

```powershell
python -m dooray_sync.cli.main sync -p m2test
dir "C:\drive\dev\dooraydrive\.dbg\m2\local"
```

로컬 폴더도 `하위2`가 되고 그 안에 `a.txt`가 그대로 있으면 통과다.

## 9. 삭제 전파 — 되돌리기 어려운 유일한 단계

Dooray 웹에서 `원격.txt`를 휴지통으로 보낸다.

```powershell
python -m dooray_sync.cli.main sync -p m2test --propagate-deletes --dry-run
```

**여기서 반드시 멈추고 숫자를 본다.**
- `실제로 사라질 항목`이 **정확히 1건**인가
- 그 1건이 `원격.txt`가 맞는가

맞을 때만 실행한다.

```powershell
python -m dooray_sync.cli.main sync -p m2test --propagate-deletes
```

**확인**: 로컬에서 `원격.txt`가 사라지고 **Windows 휴지통에 들어가 있다**(영구삭제가 아니다).

## 10. 크래시 복구

큰 파일(수십 MB)을 웹에서 `_m2_test`에 올린 뒤, 받는 도중 **Ctrl+C**로 끊는다.

```powershell
python -m dooray_sync.cli.main sync -p m2test
# 진행 중 Ctrl+C
python -m dooray_sync.cli.main status -p m2test     # 미완료 저널이 잡히는지
python -m dooray_sync.cli.main sync -p m2test       # 복구 후 정상 수렴
```

**확인**: 두 번째 실행이 `중단된 작업 복구` 절을 출력하고, 파일이 온전히 받아진다.
`.dooraysync_tmp` 안에 `.part` 찌꺼기가 남지 않아야 한다.

## 결과로 알려줄 것

각 단계의 **출력 그대로**가 가장 좋다. 특히:

1. 3단계 `--dry-run`의 동작별 건수 표
2. **4단계 결과** (`변경 없음`이 떴는지)
3. 7단계 충돌 후 `dir` 출력과 두 파일의 내용
4. 8단계 `--dry-run`의 `실제로 사라질 항목` 값
5. 실패·보호·경고가 하나라도 뜨면 그 줄 전체

출력이 잘리면(`... 외 N건`) 그 사실도 함께 알려 달라 — 잘린 출력을 근거로 판단하지 않는다(운영교훈 §13).

## 중단 신호 (하나라도 보이면 멈추고 알려 달라)

- `--dry-run`에서 예상하지 않은 **삭제** 건수
- `보호` 사유가 이해되지 않는 경우
- 같은 파일이 매 실행 반복해서 올라감(기준선 문제 재발)
- `실패` 건수가 0이 아님
