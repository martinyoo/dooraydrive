## 무엇인가

공공기관용 Dooray Drive 로컬 동기화 CLI (Windows 전용). Dooray 공식 데스크톱 앱이
공공기관 클라우드를 지원하지 않아 자체 개발했습니다.

현재 버전 **0.3.1** (`dooray_sync/__init__.py`, 태그 `v0.3.1`). 버전을 확인하는 방법 넷:

```bash
.\dsync --version
```

`doctor` 출력, 로그 첫 줄, 그리고 프로그램 폴더의 `INSTALLED.txt`에도 찍힙니다.
**프로그램이 아예 실행되지 않는 PC에서는 `INSTALLED.txt`가 유일한 답입니다.**

## 설치 · 갱신 · 롤백

일상 설치·갱신은 [설치안내.md](설치안내.md)가 정본입니다. 요지만:

- `설치.bat`이 zip을 받아 **프로그램 폴더를 통째로 교체**합니다. 파일 단위 복사는 금지입니다
  (의존이 어긋나 기동조차 못 한 실측 사례가 있습니다).
- **프로그램 폴더 안의 `설치.bat`을 더블클릭하면 1(갱신)/2(이 PC 다시 맞추기)를 묻습니다**
  (2026-09-16). 1을 고르면 그 파일이 자신을 `%TEMP%`로 빼내 거기서 폴더를 교체합니다 —
  자기가 든 폴더를 자기가 갈아 끼울 수는 없기 때문입니다. 기본값은 2입니다.
  `INSTALL.ps1`이 없는 폴더에 복사해 실행하는 예전 경로도 그대로 됩니다(질문 없이 곧장
  갱신 — 프로그램 폴더가 망가져 질문 화면까지 못 갈 때의 길).
- `설치.bat <버전>`이 `refs/tags/<버전>.zip`을 받습니다. **롤백은 `v0.2.0`부터 가능**합니다
  (되돌아갈 지점은 `v0.2.0`·`v0.3.0`·`v0.3.1`입니다).
- 교체 직후 `INSTALLED.txt`(버전·URL·시각·경로)가 남습니다.
- 동기화 실행 끝에 원격이 더 높으면 **새 버전 알림** 한 줄이 뜹니다. 자동 갱신은 하지 않습니다.
- ⚠ **갱신 전에 자동 동기화 창을 닫으세요.** 살아 있는 루프 프로세스의 `sys.path`가 교체된
  새 폴더를 가리키게 되어, 그 뒤의 지연 임포트가 옛 코드에 새 코드를 섞습니다(미실측 위험).

> **릴리스 규약**: 새 버전 알림은 main의 `__version__`을 릴리스 표시로 읽습니다.
> **릴리스마다 그 값을 올리지 않으면 동료 화면은 영원히 조용합니다.**

## CLI

`init` / `status` / `push` / `pull` / `reconcile` / `sync` / `resolve` / `doctor`.
정본은 `python -m dooray_sync.cli.main --help`입니다.

평소 운용은 명령이 아니라 동기화 폴더의 `synchere.bat` 더블클릭입니다.
자동 동기화는 `synchere.bat --auto <on|off|status|now|loop>`.

## 안전 정책 (반드시 알아야 할 것)

- **삭제는 휴지통으로만 전파됩니다.** 영구삭제 API는 코드에 아예 없습니다. 기본값은 켜짐이고,
  한 번에 **50건 또는 기준선의 20%** 이상이 사라질 계획이면 **아무것도 실행하지 않고 중단**합니다.
- **충돌은 양쪽을 모두 보존합니다.** 어떤 충돌에서도 삭제가 이기지 않습니다.
- **실행 전 `--dry-run`으로 `실제로 사라질 항목: 0건`을 먼저 확인하세요.**
- **로컬 마커(`synchere.bat`)가 등록/해제 스위치입니다.** 프로파일 루트에서 지우면 다음 실행에
  자동 해제(soft — 기준선 DB는 보존), 되돌려 놓고 실행하면 자동 재등록.
  **단 `push`/`pull`/태그 없는 `off`는 사람의 결정으로 보고 절대 자동 전환하지 않습니다.**
- `send2trash`를 쓸 수 없으면 로컬 삭제는 실행되지 않고 '보고'로만 처리됩니다 —
  `os.remove`로 대체하지 **않습니다**(불변식 I5).

## 알려진 함정 · 미수정 결함

1. **`--dry-run` 목록은 `... 외 N건`으로 잘립니다.** 그래서 **"무엇이 없다"의 증명에 쓸 수
   없습니다.** 제외 검증이 필요하면 `LocalScanner`를 프로파일 exclude로 직접 돌려 전체 집합을
   열거하세요.
2. **exclude는 CLI·도구로 못 바꿉니다.** `init`에 `--exclude`가 없습니다. `config.toml` 직접
   편집이 유일하며, 문자열 치환보다 프로그램 자신의 `load_config`/`save_config` 왕복이
   안전합니다(다른 프로파일과 `[auto]` 보존). glob 의미론: `.git/`은 컴포넌트 매칭이라 하위
   저장소의 `.git/`도 함께 걸리고, `*.env`는 `.env`를 잡지만 `*.env.example`은 안 잡습니다.
3. **업로드가 바이트를 두 번 보냅니다(미수정).** 307 리다이렉트를 받으면 파일을 다시 열어
   전체를 재전송하므로 실제 송신량이 계획 표시의 약 2배입니다. 데이터 안전성 문제는 아니고
   시간·대역폭만의 문제입니다. 개선안: 307 대상 호스트를 세션 내 한 번 학습해 캐시하거나,
   1차 홉을 빈 바디 탐침으로 바꿉니다. (`dooray_sync/api/client.py`의 `upload_file`)
4. **원격 휴지통 이동은 실계정에서 확인하지 않았습니다** — 페이크 원격으로만 검증했습니다.
5. 경로 해석 대소문자 결함은 수정됐지만(정확 일치 우선 + casefold 폴백, 409를 기존 폴더
   반환으로 흡수) **실계정 재현은 하지 않았습니다.**
6. 이어올리기가 없어 큰 파일 전송이 끊기면 처음부터 다시 보냅니다.

## 기관 확인이 남은 것

검토보고서 §7의 기관 확인 항목 중 **IP ACL · 보안 내규 · 토큰 정책**이 미확인입니다.
플랜 용량 한도는 실측으로 해소됐습니다.

동료 PC 배포 전 확인할 것 둘: **휴지통 설정**(`pywin32`가 없으면 `send2trash`가 legacy 경로를
타는데, 휴지통에 넣을 수 없는 상황에서 확인 창 없이 영구삭제되고 API는 성공을 반환합니다 —
무증상 소실 경로입니다)과 **Dooray 휴지통 보존 기간**(실측 기록이 없습니다).

## 확인 방법

**프로파일·경로·정책의 실제 값은 이 문서가 아니라 명령이 정본입니다.**

| 도구 | 용도 |
|---|---|
| `python tools\set_sync_mode.py --list` | 프로파일과 sync 정책 현황 |
| `python diag.py` | 설정 경로·실행 계정·APPDATA 실경로 진단 |
| `python diag.py <프로파일>` | DB 기준선 vs 로컬 스캔 대조, reconcile 대상 수 |
| `.\dsync doctor -p <프로파일>` | 토큰·연결·긴 경로·DB 무결성 |
| `python -m pytest tests -q` | 테스트 전건 통과가 릴리스 판정 기준입니다 |
