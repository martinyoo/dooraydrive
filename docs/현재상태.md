### 아래는 검증 절차 원본 (재현용)

**절차는 [M2_실계정검증.md](M2_실계정검증.md)에 11단계로 정리했다.** 파일럿 프로파일이 아니라

`send2trash`는 **설치되어 있다**(2.1.0, 2026-08-03 확인 — `Python311\Lib\site-packages`).
없을 경우에는 로컬 삭제가 실행되지 않고 '보고'로만 처리된다(안전한 기본값).

삭제 경로는 자동 테스트에서 **실제로 실행해** 확인했다 — 파일이 휴지통으로 가고 DB 레코드가
정리되는 것, 그리고 send2trash를 쓸 수 없을 때 `os.remove`로 대체하지 **않고** 예외를 올리는 것
(불변식 I5)까지. 다만 이는 로컬 파일시스템 기준이고, **원격 휴지통 이동은 아직 실계정에서
확인하지 않았다**(페이크 원격으로만 검증).

### 성능 결함: 307 리다이렉트로 업로드 바이트가 2배 전송된다 (2026-08-02 확인)

`upload_file`은 1차 홉에 **파일 전체를 실어 보내고**, 307을 받으면 파일을 다시 열어 **전체를 재전송**한다.
즉 모든 업로드의 실제 송신량이 계획 표시의 2배다.

- 근거: [api/client.py](../dooray_sync/api/client.py) `upload_file` — 1차 홉 `files={"file": (filename, f)}` 전송 후
  `if r1.status_code in _REDIRECT_STATUSES:` 에서 `with open(...) as f2:` 로 재오픈해 2차 홉 전송.
- 주석에 의도가 명시돼 있다: *"1차 요청에서 파일 객체가 이미 소진되어 그대로는 재전송할 수 없다."*
- 실측 영향: 8.88GB 초기 업로드 → 실제 약 17.8GB 송신. WORK 71GB → 약 142GB.
- 개선안: 307 대상 호스트(`file-api.gov-dooray.com`)는 항상 같으므로 **세션 내에서 한 번 학습해 캐시**하고
  이후 업로드는 2차 홉으로 직행한다. 또는 1차 홉을 빈 바디 탐침으로 바꾼다.
- 데이터 안전성 문제는 아니다. 시간·대역폭만의 문제이므로 M4로 미룬다.

### 결함: 경로 해석은 대소문자 구분, 서버 중복 검사는 무시 (2026-08-02 발견)

로컬 `Writing`을 원격 `Writing`으로 `init --create-remote` 하면 **HTTP 409 `Duplicate request`**로 실패한다.
원격에는 이미 `WRITING`(대문자)이 있는데, 경로 해석기는 대소문자를 구분해 이를 찾지 못하고

- 우회(수정 전): 원격의 실제 표기에 맞춰 `--remote-path "WRITING"`으로 지정한다.

> **수정 완료 (2026-08-02, 브랜치 `m2-bidirectional`)** — 세 곳을 고쳤다.

## 다음 세션이 반드시 지켜야 할 것

**작업 디렉터리(`C:\drive\dev\dooraydrive`) 밖에 쓰기·삭제 명령을 실행하지 말 것.**

이번 세션에서 실제로 사고가 있었다. 어시스턴트 실행 환경과 사용자 PC의 파일시스템 경계가 경로마다 다르게 동작했다 — `%APPDATA%`는 분리되어 있어 어시스턴트가 만든 설정이 사용자 PC에 반영되지 않았고, 반대로 `%LOCALAPPDATA%`는 공유되어 있어 어시스턴트의 `rm -rf`가 **사용자의 상태 DB를 실제로 삭제**했다. 그 결과 원인 진단이 세 차례 빗나갔다.

따라서:

- 설정(`%APPDATA%\dooray-sync`)·상태 DB(`%LOCALAPPDATA%\dooray-sync`)·자격 증명은 **어시스턴트가 직접 만들거나 지우지 않는다.** 사용자가 실행할 명령을 안내한다.
- 재현·실험이 필요하면 `DOORAY_SYNC_CONFIG_DIR` / `DOORAY_SYNC_STATE_DIR`를 프로젝트 폴더 하위로 지정해 격리한다(`.gitignore`에 `.dbg/` 추가되어 있음).
- 사용자 PC의 상태는 어시스턴트가 조회한 결과가 아니라 **사용자가 실행한 `python diag.py`의 출력**으로만 판단한다.

## 진단 도구

| 도구 | 용도 |
|---|---|
| `python diag.py` | 설정 경로·실행 계정·APPDATA 실경로 진단 |
| `python diag.py <프로파일>` | DB 기준선 vs 로컬 스캔 키 대조, reconcile 대상 수 |
| `.\dsync doctor -p <프로파일>` | 토큰·연결·긴 경로·DB 무결성 |
