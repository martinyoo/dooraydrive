# dooray_sync 모듈 인터페이스 규약 (M2 — 양방향 + 충돌 + 저널 복구)

M1 규약([모듈규약.md](모듈규약.md))의 **연장**이다. M1에 적힌 공통 규칙(§0)·금지사항(§12)은
전부 그대로 유효하며, 이 문서는 M2에서 **새로 추가되는 모듈**의 계약만 정의한다.

- 근거: [구현계획서.md](구현계획서.md) §3.3(결정표 13케이스) · §4(A1~D1) · §5(M2), [검토보고서.md](검토보고서.md) §3.3(changes 실측)
- 병렬 구현의 단일 진실 소스다(운영교훈 §6). 시그니처를 임의로 바꾸지 않는다.

## 0. M2 최상위 불변식 (모든 모듈이 지켜야 함)

이 6개를 어기는 구현은 계약 위반이다. 각 항목 뒤 괄호는 이를 검사하는 테스트다.

| # | 불변식 | 근거 |
|---|---|---|
| I1 | **모르면 아무것도 지우지 않는다.** 원격 뷰가 불완전(델타)할 때 "관측되지 않음"은 **삭제가 아니라 변경 없음**이다 | R8/R11 — 대량 오삭제 |
| I2 | **삭제는 어떤 충돌에서도 패배한다.** 한쪽 삭제 vs 반대쪽 수정이면 **살아 있는 쪽을 복원**한다(결정표 9·10) | 구현계획서 §1 최우선 원칙 |
| I3 | **양쪽이 다르게 바뀌면 양쪽을 모두 보존한다.** 로컬을 충돌 사본으로 남긴 뒤 원격을 받는다(결정표 6) | 유실 0건 |
| I4 | **base는 반쪽으로 기록하지 않는다.** 저널 committed와 files 갱신은 **한 트랜잭션**이며, 크래시 복구는 base를 추정으로 채우지 않고 **재검사 대상으로 표시**만 한다 | M2 완료 기준(무손실 수렴) |
| I5 | **영구삭제는 존재하지 않는다.** 원격은 `move_to_trash`, 로컬은 `send2trash`뿐. `os.remove`로 사용자 파일을 지우는 코드를 쓰지 않는다(임시파일 제외) | 규약 §12-3, C5 |
| I6 | **커서를 근거로 최신이라고 단정하지 않는다.** `sync_status != 'synced'`인 레코드는 델타 모드에서도 **매번 원격 메타를 직접 확인**한다 | 델타 모드의 조용한 누락 차단 |

## 2. `dooray_sync/core/remote.py` (신규 — B1~B5)

원격 상태 축(R)을 만든다. **전체 순회(full)** 와 **changes 델타(delta)** 두 경로가 있고,
둘 다 같은 `RemoteView`를 낸다. 델타 뷰는 **불완전**하며 그 사실을 뷰가 스스로 들고 다닌다(I1).

```python
@dataclass(frozen=True)
class RemoteEntry:
    rel_path: str            # 동기화 루트 기준 상대경로('/' 구분, NFC)
    rel_path_key: str
    is_dir: bool
    file_id: str
    parent_id: str = ""
    server_name: str = ""    # 서버 저장명 정본(R14)
    version: int | None = None
    revision: int | None = None
    size: int | None = None
    md5: str | None = None   # changes에만 존재. 목록 API 응답에는 없다(실측)

@dataclass
class RemoteView:
    entries: dict[str, RemoteEntry]      # rel_path_key -> 관측된 항목
    deleted_keys: set[str] = field(default_factory=set)   # 원격 삭제로 확정된 키
    moved_out_keys: set[str] = field(default_factory=set) # 동기화 범위 밖으로 이동됨
    is_complete: bool = False            # True면 entries가 원격 전체 스냅샷
    cursor: Cursor = field(default_factory=Cursor)        # 이 뷰 생성 후 저장할 커서
    unsyncable: list[tuple[str, str]] = field(default_factory=list)
    collisions: list[str] = field(default_factory=list)   # 경로키 충돌로 제외한 항목
    truncated: bool = False              # 페이징 한계 도달 등으로 잘렸는지
    probed_ids: set[str] = field(default_factory=set)     # 개별 메타 조회로 확인한 file_id
    probe_skipped: int = 0               # 예산 초과로 확인 못 한 건수 — 반드시 보고
    changes_seen: int = 0
    subtrees_relisted: int = 0

    def observed(self, key: str) -> bool
        """이번 뷰가 그 키의 원격 상태를 실제로 확인했는가.
        is_complete면 항상 True. 델타면 entries/deleted_keys/moved_out_keys에 있을 때만 True."""

    def by_file_id(self) -> dict[str, RemoteEntry]
        """file_id → 항목. 원격 이동/개명 판정(결정표 12)의 근거."""

> 지운 적이 없으므로 `moved_out_keys`에 넣어 **보고만** 한다. 삭제로 취급하면 로컬 파일이
> 휴지통으로 간다(I2 위반).

class RemoteCollector:
    """원격 뷰 생성기. DriveAPI 호출은 전부 여기에 모은다."""

    def __init__(self, drive: DriveAPI, drive_id: str, remote_prefix: str,
                 root_id: str, *, exclude: Sequence[str] = (),
                 logger: logging.Logger | None = None) -> None

    def full(self) -> RemoteView

        - `walk`로 순회하며 subType=='trash'는 제외(DriveAPI가 이미 배제).
        - 이름 문제(name_issue)·경로키 충돌 항목은 entries에 넣지 않고 unsyncable/collisions에 모은다.
        - 커서는 건드리지 않는다(호출측이 별도로 advance_to_tip 또는 기존 커서 유지)."""

    def delta(self, cursor: Cursor, *, known_by_file_id: dict[str, str] | None = None,
              dirty_file_ids: Iterable[str] = (), max_items: int = 20000,
              max_probes: int = 500,
              on_item: Callable[[str], None] | None = None) -> RemoteView
        """changes 소비(B1~B4). is_complete=False.

        B1: 종료 조건은 **0건 응답뿐**. `len(items) < size`로 끊지 않는다(DriveAPI.iter_changes 사용).
        B2: 커서는 (revision, file_id) 복합. 미전진 시 중단.
        B3: **net-뷰 전제** — 항목의 name/path를 정본으로 수용한다. `deleted`는 id·type·revision만
            오므로 DB에서 file_id로 역참조하고, **미지 id의 deleted는 무시**한다(정상 동작).
        B4: 폴더 `updated`를 받으면 **그 폴더 하위 트리를 목록 API로 재열람**해 자손을 전부
            entries에 넣는다. 빠뜨리면 하위 전체가 '원격에서 사라짐'으로 보여 대량 오삭제가 된다.
            같은 폴더를 한 패스에서 두 번 재열람하지 않는다(방문 집합).
        I6: `dirty_file_ids`(sync_status != 'synced'인 레코드의 file_id)는 changes에 없더라도
            `get_file_meta`로 개별 확인해 entries 또는 deleted_keys에 반영한다. 조회가
            '없음/권한없음'으로 실패하면 삭제로 단정하지 말고 그 키를 관측하지 않은 것으로 둔다.

        max_items를 넘으면 truncated=True로 표시하고 그 지점 커서를 반환한다 — 호출측은
        이번 패스를 부분 처리로 간주하고 다음 실행에서 이어받는다.
        `dirty_file_ids` 개별 조회는 max_probes로 제한한다(init 직후에는 미완료 레코드가
        수천 건이라 그대로 두면 조회가 폭주한다). 자른 건수는 probe_skipped에 담아
        **반드시 사용자에게 보고**하고 'sync --full'을 권한다.
```

## 3. `dooray_sync/core/differ.py` (신규 — 결정표 13케이스)

**순수 함수다. 네트워크·파일시스템 접근을 하지 않는다.** 13케이스를 그대로 단위 테스트할 수 있어야
하므로 이 규칙은 타협하지 않는다. 내용 비교에 원격 MD5가 필요한 경우만 주입된 콜백을 쓴다.

```python
# kind 값 — planner/executor가 그대로 소비한다
KIND_MKDIR_LOCAL    = "MKDIR_LOCAL"
KIND_MKDIR_REMOTE   = "MKDIR_REMOTE"
KIND_UPLOAD_NEW     = "UPLOAD_NEW"
KIND_UPLOAD_VERSION = "UPLOAD_VERSION"
KIND_DOWNLOAD_NEW   = "DOWNLOAD_NEW"
KIND_DOWNLOAD_UPDATE= "DOWNLOAD_UPDATE"
KIND_CONFLICT       = "CONFLICT"        # 로컬 사본 보존 → 원격 수신 → (옵션) 사본 업로드
KIND_LOCAL_MOVE     = "LOCAL_MOVE"      # 원격 이동/개명을 로컬에 반영(os.replace)
KIND_REMOTE_MOVE    = "REMOTE_MOVE"     # 로컬 이동/개명을 원격에 반영(move/rename)
KIND_LOCAL_TRASH    = "LOCAL_TRASH"
KIND_REMOTE_TRASH   = "REMOTE_TRASH"
KIND_TOUCH_BASE     = "TOUCH_BASE"      # 전송 없이 base만 정정
KIND_FORGET         = "FORGET"          # 양쪽에서 사라진 항목 — DB 레코드만 정리
KIND_REPORT         = "REPORT"          # 실행 없음. 사용자에게 알리기만
KIND_PROTECT        = "PROTECT"         # 덮어쓰기를 거부하고 보존
KIND_UNSYNCABLE     = "UNSYNCABLE"

@dataclass(frozen=True)
class Decision:
    case: int                 # 결정표 번호 1~13 (해당 없으면 0)
    kind: str
    rel_path: str
    key: str
    is_dir: bool = False
    local: LocalEntry | None = None
    remote: RemoteEntry | None = None
    base: FileRecord | None = None
    new_rel_path: str = ""    # MOVE 계열의 목적지
    reason: str = ""          # 사용자에게 보이는 한 줄 설명(한국어)

@dataclass
class DiffStats:
    unchanged: int = 0
    skipped_unobserved: int = 0     # 델타 뷰에서 관측되지 않아 판단 보류한 키
    md5_probes: int = 0
    md5_probe_skipped: int = 0      # 예산 초과로 확인하지 못한 건수(반드시 보고할 것)

def diff(*, base: dict[str, FileRecord], local: dict[str, LocalEntry],
         remote: RemoteView, propagate_deletes: bool = False,
         hash_local: Callable[[LocalEntry], LocalEntry] | None = None,
         md5_probe: Callable[[RemoteEntry], str | None] | None = None,
         md5_probe_budget: int = 200,
         local_unobserved: Sequence[str] = ()) -> tuple[list[Decision], DiffStats]
    """3-way diff. base/local/remote의 키는 전부 rel_path_key.

    판정 규칙(구현계획서 §3.3 결정표):

    | # | 상황 | 산출 |
    |---|---|---|
    | 1 | B없음 · L있음 | UPLOAD_NEW (폴더면 MKDIR_REMOTE) |
    | 2 | B없음 · R있음 | DOWNLOAD_NEW (폴더면 MKDIR_LOCAL) |
    | 3 | B없음 · 양쪽 신규 | MD5 동일 → TOUCH_BASE(병합) / 다르면 CONFLICT |
    | 4 | L변경 · R불변 | UPLOAD_VERSION |
    | 5 | L불변 · R변경 | DOWNLOAD_UPDATE |
    | 6 | L변경 · R변경 | **CONFLICT** (내용 MD5가 같으면 TOUCH_BASE로 강등 — 가짜 충돌 제거) |
    | 7 | L삭제 · R불변 | propagate_deletes ? REMOTE_TRASH : REPORT |
    | 8 | L불변 · R삭제 | propagate_deletes ? LOCAL_TRASH : REPORT |
    | 9 | L삭제 · R변경 | **DOWNLOAD_NEW + REPORT** — 보존 승리(I2). 삭제를 전파하지 않는다 |
    | 10 | L변경 · R삭제 | **UPLOAD_NEW + REPORT** — 보존 승리(I2) |
    | 11 | L이동/개명 | REMOTE_MOVE |
    | 12 | R이동/개명 | LOCAL_MOVE |
    | 13 | 이동+수정 복합 | 이동을 먼저 산출하고 나머지는 다음 패스로 미룬다. 판단 불가면 CONFLICT |

    핵심 판정 기준:
    - **원격 변경 감지 키는 `(version, server_name, parent_path)` 조합**이다. 이름 변경은 version을
      올리지 않는다(R13) — version만 비교하면 개명을 영구히 놓친다.
    - **로컬 변경 감지는 (mtime_ns, size) 게이트 후 MD5**. 게이트가 같으면 변경 없음으로 본다.
    - 내용 동일성 보조 판정은 MD5. 양쪽이 같은 내용이면 충돌로 만들지 않는다(가짜 충돌 제거).
    - `remote.observed(key)`가 False면 **원격은 base와 같다고 본다**(I1). 관측되지 않은 키에서
      절대 R삭제를 유도하지 않는다. 이 경우 DiffStats.skipped_unobserved를 올린다.
    - 반대로 **완전 뷰(is_complete)에서 목록에 없으면 그것은 삭제다.** 삭제 판정을 changes의
      톰스톤에만 의존하면 `--full` 전체 재조정이 원격 삭제를 영원히 감지하지 못한다.
      → 판정에 쓰는 값은 `r_deleted`가 아니라 `r_absent = r_deleted or (없음 and is_complete)`.
    - `hash_local`은 로컬 MD5가 필요할 때만 부르는 주입 콜백이다(보통 `LocalScanner.fill_md5`).
      **이 콜백과 `md5_probe` 외에는 어떤 IO도 하지 않는다** — 순수성의 경계가 정확히 여기다.
      콜백이 OSError를 올리면 DiffStats.hash_failures에 모으고 그 항목은 PROTECT로 남긴다.
      `fill_md5`는 `dataclasses.replace`로 **새 객체**를 돌려주므로 계산 결과를 **원본 entry에
      되쓴다**. 되쓰지 않으면 Decision이 든 entry의 md5가 None으로 남아 executor가
      `local_md5=NULL`을 기록하고, 그 파일은 다음 실행부터 영원히 PROTECT가 된다.
    - **`local_unobserved`(I1의 로컬 축)**: 스캔이 건너뛴 경로들(`LocalScanner.skipped`).
      그 경로와 하위는 '로컬에 없음'이 아니라 '모름'으로 보고 **삭제 판정을 내지 않는다.**
      스캐너는 접근 거부·나열 중단 시 그 항목만 건너뛰고 계속 진행하므로, 이것을 넘기지
      않으면 일시적 IO 오류가 그대로 원격 삭제로 전파된다.
    - base가 있는데 local_md5가 없는 파일(init 직후 등)은 **어느 쪽이 최신인지 모른다** —
      M1 push의 '보류'와 같은 취급으로 PROTECT를 낸다(reason에 reconcile 안내).
    - 이동 승격: base에 있던 키가 로컬에서 사라지고, 같은 (size, md5)를 가진 base 없는 로컬
      신규 항목이 정확히 **1건** 있으면 삭제+신규가 아니라 이동으로 재해석한다(11번). 후보가
      2건 이상이면 이동으로 승격하지 않는다(오판이 삭제로 이어지는 것을 막는다).
    - 원격 이동 감지는 **file_id 역색인**으로 한다: base의 file_id가 원격에서 다른 경로로
      관측되면 12번. 파일이 사라진 것이 아니다.
    - 디렉터리 이동(11/12의 폴더판)은 자손을 이 패스에서 처리하지 않는다. Decision.reason에
      "하위 항목은 다음 실행에서 처리"를 남기고, planner가 해당 서브트리의 다른 Decision을 건다.
    - `md5_probe`는 **case 3/6에서 원격 MD5를 모를 때만** 호출한다(목록 API에는 hash가 없다).
      예산(md5_probe_budget)을 넘으면 호출하지 않고 CONFLICT로 남긴 뒤 md5_probe_skipped를 센다 —
      **조용히 건너뛰지 않는다.** 크기가 다르면 probe 없이 내용이 다르다고 판정한다.
    """

def conflict_copy_name(rel_path: str, when: datetime) -> str
    """'문서.docx' → '문서 (충돌 2026-08-02 1530).docx' (구현계획서 §3.3 6번).
    확장자가 없으면 이름 끝에 붙인다. 결과가 Windows에 저장 불가한 이름이 되면 안 된다."""
```

**CONFLICT 실행 순서(고정)** — 순서를 바꾸면 유실 창이 생긴다.

1. 로컬 원본을 `conflict_copy_name()`으로 **개명**(같은 폴더 안 `os.replace`, 대상이 이미 있으면 접미 증가)
2. `conflicts` 테이블에 기록 + 저널 'transferred'
3. 원격을 원래 경로로 원자적 다운로드(C1) — 이제 원본 경로는 비어 있으므로 덮어쓸 것이 없다
4. `p.upload_conflict_copy`가 True면 사본을 원격에 **신규 업로드**(POST)
5. base 갱신 + 저널 'committed'

3번이 실패해도 1번의 사본이 남아 있으므로 로컬 내용은 유실되지 않는다.

`UPLOAD_NEW`를 실행하려는데 원격 부모 폴더에 같은 이름이 **이미 있다면**, 그것이
`base.file_id`와 같은 파일일 때만 새 버전으로 올린다. id가 다르면 **덮어쓰지 않고**
`pending_upload`로 표시한 뒤 보고한다 — 그 파일은 우리가 모르는 남의 최신본일 수 있다.

```
      keep both  : 아무것도 하지 않고 해결 처리(기본)
```

종료코드는 M1과 동일(0/1/2/3). 다음은 **실패가 아니다**: 보존 승리(9·10), 충돌 사본 생성,
보호(PROTECT), 삭제 미전파 보고. 실패는 전송·API 오류와 `BulkDeleteAbort`뿐이다.

## 9. M2 금지 사항 (M1 §12에 더해)

1. 원격 뷰가 불완전할 때 "없으니 삭제됐다"고 판정하지 말 것 (I1 — 대량 오삭제)
2. 삭제를 수정보다 우선시키지 말 것 (I2 — 결정표 9·10)
3. 충돌에서 한쪽을 버리지 말 것 (I3 — 사본을 먼저 만들고 나서 받는다)
4. 저널 'committed'와 files 갱신을 서로 다른 트랜잭션에 두지 말 것 (I4)
5. `send2trash` 실패를 `os.remove`로 폴백하지 말 것 (I5)
6. `version`만으로 원격 변경을 판정하지 말 것 (R13 — 개명은 version 불변)
7. 폴더 `updated`를 받고 하위 재열람을 건너뛰지 말 것 (R8/B4)
8. differ·planner에 네트워크·파일시스템 접근을 넣지 말 것 (13케이스 테스트 가능성)
9. 예산·상한으로 건너뛴 항목을 조용히 버리지 말 것 — 반드시 건수를 보고할 것
10. 파일럿 중인 `push`/`pull`의 동작을 바꾸지 말 것
