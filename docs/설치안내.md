# 다른 PC에 설치하기

재택 PC·회사 PC 등 두 번째 컴퓨터에 이 도구를 설치하는 절차입니다.

> **먼저 확인**: 이 도구는 **Windows 전용**입니다. 긴 경로(`\\?\`)와 파일 잠금 처리에
> Windows API를 직접 씁니다.

## 가장 쉬운 방법 — `설치.bat` 하나만 받아 더블클릭

`설치.bat` **파일 하나면 됩니다.** Python도 프로그램 본체도 미리 받을 필요가 없습니다.

1. `설치.bat`을 아무 곳(바탕화면 등)에 두고 **더블클릭**
2. 물어보는 것은 둘뿐 — **설치 폴더**(엔터 = 기본값)와 **API 토큰**(붙여넣기, 화면에 표시되지 않음)

설치 프로그램이 하는 일: 설치 폴더 결정 → Python 확인·자동 설치 → 저장소 내려받기 →
차단 해제 → 의존성 설치 → 토큰 등록 → 연결 확인.
중간에 끊겨도 다시 더블클릭하면 끝난 단계는 건너뜁니다.

### 설치 폴더 정하기

**C:로 강제되지 않습니다.** 다음 순서로 정해지고, 위쪽이 이깁니다.

| 순위 | 방법 | 예 |
|---|---|---|
| 1 | 첫 번째 인자 (폴더를 이 파일에 끌어다 놓아도 됨) | `설치.bat D:\dooraydrive` |
| 2 | `DSYNC_TARGET` 환경변수 | `set DSYNC_TARGET=D:\dooraydrive` |
| 3 | 물어볼 때 입력 | `Folder: D:\dooraydrive` |
| 4 | **`설치.bat`이 놓인 드라이브** (기본값) | D:에 두고 실행 → `D:\dooraydrive` |

4번 덕분에 보통은 **`설치.bat`을 원하는 드라이브에 두고 엔터만 누르면** 됩니다.
드라이브 이름만 줘도(`D:`) `D:\dooraydrive`로 해석합니다.

설치가 끝나면 프로그램 위치가 `DSYNC_HOME` 사용자 환경변수에 기록됩니다 —
`synchere.bat`이 프로그램을 찾는 데 씁니다(환경변수가 없어도 각 드라이브의
`\dooraydrive`를 훑어 찾습니다).

**동기화 폴더는 설치 때 정하지 않습니다.** 설치가 끝나면, 동기화할 폴더에
설치 폴더의 `synchere.bat`를 복사해 더블클릭하세요 — 그 폴더가 등록되고 첫 동기화가
시작됩니다(자세한 동작은 아래 [6. 동기화 폴더 등록](#6-동기화-폴더-등록--syncherebat) 참조).

```powershell
.\INSTALL.ps1 -Check     # 이 PC가 준비됐는지 점검만 (아무것도 바꾸지 않음)
```

### 설계 메모 (고치기 전에 읽을 것)

- **`설치.bat`은 순수 ASCII로 유지한다.** 주석에도, 자기 파일명을 참조하는 경로에도 한글을
  넣지 않는다. cmd는 `.bat`을 콘솔 코드페이지(한글 Windows 기본 CP949)로 읽어 UTF-8 한글이
  깨지고, **`chcp 65001`도 해결책이 아니다** — 라벨과 `goto`가 있는 실제 파일에서 cmd가
  멀티바이트 줄을 잘못 끊어 한글 조각을 명령으로 실행한다(2026-08-04 실측).
  한글은 전부 `INSTALL.ps1`(UTF-8 BOM)에 둔다.
- `-ExecutionPolicy Bypass`는 필수다. **zip으로 받은 파일에는 '인터넷에서 받음' 표시(MOTW)가
  붙어 기본 정책(RemoteSigned)이 `.ps1` 실행을 거부한다.** 설치 프로그램은 시작하면서 이
  표시를 먼저 해제한다.
- 프로파일 생성은 설치에서 **하지 않는다**(2026-08-10 변경). 특정 사용자의 폴더 목록을
  하드코딩한 사전 등록은 동료 PC에 맞지 않는다. 등록은 사용 시점에 `synchere.bat`가 한다
  (`tools/sync_here.py`의 유도 사슬). **`SETUP.ps1`은 2026-09-14에 삭제했다** — 하드코딩된
  폴더 목록과 특정 계정의 drive_id를 들고 있었고, 재실행이 기준선을 훼손했다.
  `SETUP-2ND-PC.ps1`은 '발견'(원격 마커로 동기화 루트 후보 보기) 하나만 남기고 축소했다.

아래는 **수동 절차**입니다. 설치 프로그램이 막힐 때나 무엇을 하는지 확인하고 싶을 때 보세요.

> 쓰세요 — 그쪽만 설치 스탬프(`INSTALLED.txt`)를 남기고, 버전 지정(되돌리기)이 되며,
> 교체 실패 시 옛 사본을 되돌려 놓습니다. 아래 수동 경로에는 그 셋이 다 없습니다.

폴더를 `C:\dooraydrive` 로 옮깁니다.

**`git clone`으로 받아서 그 폴더를 프로그램 폴더로 쓰지 마세요.** 그렇게 두면 개발 중인
코드가 매일 실제 파일을 동기화하게 됩니다. `설치.bat`은 `.git`이 있는 폴더에서 실행되면
그 사실을 경고합니다.

> **zip으로 받았다면 차단을 먼저 풀어야 합니다.** 탐색기로 압축을 풀면 파일에
> '인터넷에서 받음' 표시가 붙고, 기본 실행 정책이 `.ps1` 실행을 거부합니다
> (`running scripts is disabled on this system`). PowerShell에서 한 번만:
>
> ```powershell
> Get-ChildItem C:\dooraydrive -Recurse | Unblock-File
> ```
>
> `설치.bat`을 쓰면 이 단계가 자동으로 처리되므로 신경 쓰지 않아도 됩니다.

> 이후 설명은 `C:\dooraydrive`에 두었다고 가정합니다. 다른 경로(예: `D:\dooraydrive`)에
> 두었다면 그 경로로 바꿔 읽으세요 — `설치.bat`은 설치 폴더를 물어봅니다.

토큰은 **PC마다 따로 등록**해야 합니다(설정 파일에 저장되지 않고 Windows 자격 증명 관리자에 들어갑니다).

> 가지므로 메일·메신저로 보내지 마세요.

## 6. 동기화 폴더 등록 — synchere.bat

### 방법 A — synchere.bat 더블클릭 (권장)

동기화할 폴더에 설치 폴더의 `synchere.bat`를 **복사**해 넣고 **더블클릭**합니다.
그 폴더가 동기화 대상으로 등록되고 바로 첫 동기화가 시작됩니다.

원격 경로는 추정하지 않고 다음 순서로 **유도**합니다:

1. **형제 유도** — 같은 부모 폴더 아래에 이미 등록된 폴더가 있으면 그 결합에서 유도
   (예: `업무\2025`가 등록돼 있으면 그 옆의 `업무\2024` → 원격 `업무/2024`)
2. **원격 마커 발견** — 다른 PC에서 이미 동기화하던 같은 이름의 폴더(원격에 `synchere.bat`
   마커가 있음)를 찾아 결합 — **그 내용을 이 PC로 이어받습니다.** 두 번째 PC 설정은 이걸로
   끝입니다: 같은 이름의 빈 폴더를 만들고 synchere.bat를 넣어 실행하면 됩니다.
   같은 이름이 여럿이면 자동 결합하지 않고 목록을 보여 줍니다.
3. **최상위 동명 폴더** — 드라이브 최상위에 같은 이름의 폴더가 있으면 결합
4. **신규** — 드라이브 최상위에 같은 이름의 원격 폴더를 새로 만듭니다

등록 해제는 폴더에서 `synchere.bat`를 지우면 됩니다(다음 실행 때 해제, 기준선은 보존 —
파일을 다시 넣고 실행하면 재등록). 프로그램 폴더 안의 원본과 드라이브 루트에서는 실행해도
등록되지 않습니다.

> **로컬에 파일이 이미 있는 폴더**를 기존 원격 폴더에 결합하면, 같은 경로의 파일들은
> "보류 — 기준선 없음"으로 멈출 수 있습니다. 그때는 `.\dsync reconcile -p 프로파일`을
> 한 번 실행해 내용을 대조하세요(같으면 기록만 하고 전송하지 않습니다).

### 방법 B — 직접 지정

기존 PC와 **같은 원격 폴더**를 지정하되, 로컬 경로는 이 PC에 맞게 정하면 됩니다.

```bash
.\dsync init -p 프로파일이름 --remote-path "업무/2026" --local-root "D:\Dooray\업무 2026"
```

- `-p` 는 프로파일 이름입니다. 폴더별로 하나씩 만듭니다(기존 PC와 같은 이름을 쓰면 헷갈리지 않습니다).
- `--remote-path` 는 **기존 PC와 정확히 같게** 지정해야 같은 폴더를 봅니다.
- `--local-root` 는 이 PC에서 쓸 폴더입니다. 없으면 자동으로 만듭니다.
- 드라이브를 고르라고 물으면 개인 드라이브를 선택하세요(`--drive-id`로 미리 지정해도 됩니다).

동기화할 폴더가 여러 개면 프로파일을 폴더 수만큼 만듭니다(프로파일 1개 = 폴더 1개).

```bash
.\dsync init -p 프로파일A --remote-path "WORK/폴더A" --local-root "D:\Dooray\폴더A"
.\dsync init -p 프로파일B --remote-path "WORK/폴더B" --local-root "D:\Dooray\폴더B"
```

> 원격에 아직 없는 폴더를 새로 만들면서 시작하려면 `--create-remote`를 붙입니다.
> 오타로 엉뚱한 폴더가 생기는 것을 막기 위해 기본값은 "없으면 실패"입니다.

## 7. 파일 받기

방법 A(synchere.bat)로 등록했다면 첫 동기화가 이미 실행됐으므로 이 단계는 필요 없습니다.
방법 B로 등록했다면 직접 받습니다:

```bash
.\dsync pull -p 프로파일 --dry-run    # 무엇을 받을지 먼저 확인
.\dsync pull -p 프로파일
```

**중단되어도 안전합니다** — 다시 실행하면 이미 받은 것은 건너뛰고 남은 것만 받습니다.
받는 중에는 임시파일에 쓰고 검증 후 교체하므로, 끊겨도 반쪽짜리 파일이 남지 않습니다.
큰 폴더는 수십 분 걸릴 수 있습니다(실측 ~11GB에 수십 분).

> **로컬에 파일이 이미 있다면** 이 순서가 아닙니다. `pull`이 전부 "보류 — 기준선 없음"으로
> 멈춥니다. 그때는 `.\dsync reconcile -p 프로파일`을 먼저 실행해 내용을 대조하세요
> (같으면 기록만 하고 전송하지 않습니다).

## 이후 사용법

**평소에는 명령을 칠 일이 없습니다.** 동기화 폴더의 `synchere.bat`을 더블클릭하면 양방향
동기화가 끝납니다. 아래 명령은 뭔가 확인하거나 한쪽 방향만 하고 싶을 때 쓰세요.

| 하고 싶은 것 | 명령 |
|---|---|
| 양방향 동기화(평소 하는 일) | `.\dsync sync -p 프로파일` |
| 원격의 최신 파일 받기만 | `.\dsync pull -p 프로파일` |
| 내가 고친 파일 올리기만 | `.\dsync push -p 프로파일` |
| 현재 상태 보기 | `.\dsync status -p 프로파일` |
| 기준선 맞추기("보류 N건"이 나올 때) | `.\dsync reconcile -p 프로파일` |
| 충돌 처리하기 | `.\dsync resolve -p 프로파일` |
| 문제 진단 | `.\dsync doctor -p 프로파일` |
| 프로그램 버전 보기 | `.\dsync --version` |

**항상 `--dry-run`을 먼저 붙여 계획을 확인하는 습관을 들이세요.** 계획만 출력하고 아무것도 바꾸지 않습니다.

## 자동 동기화 (켜 두면 알아서 돕니다)

더블클릭을 잊어도 되도록, 로그인할 때 뜨는 작은 창 하나가 주기적으로 동기화합니다.
작업 표시줄에만 있고 화면을 가리지 않습니다.

```bash
.\synchere.bat --auto on       # 이 폴더를 자동 대상으로 등록 (로그온 자동 기동도 함께)
.\synchere.bat --auto status   # 지금 상태 보기 (네트워크를 쓰지 않습니다)
.\synchere.bat --auto off      # 이 폴더만 자동에서 빼기
.\synchere.bat --auto loop     # 창을 지금 바로 띄우기
```

알아 둘 것 셋:

- **창을 닫으면 자동 동기화도 멈춥니다.** 다음 로그온 때 다시 뜹니다. 지금 바로 다시
  띄우려면 시작프로그램 폴더의 `dooray-sync-loop.bat`을 더블클릭하거나 `--auto loop`를 쓰세요.
- **창 안을 마우스로 클릭하지 마세요.** Windows 콘솔의 QuickEdit 때문에 클릭하는 순간
  멈춥니다(아무 키나 누르면 풀립니다). 프로그램이 이 기능을 꺼 두지만, 창이 멀쩡해
  보이는데 동기화만 죽는 가장 조용한 실패 모드라 알아 두는 편이 좋습니다.
- **사람이 판단해야 하는 일은 자동으로 하지 않습니다.** 충돌이나 대량 삭제가 있으면
  그냥 기다립니다. 그런 것이 쌓이면 다음에 `synchere.bat`을 직접 실행할 때 맨 위에
  알려 줍니다 — 그때 처리하시면 됩니다.

## 두 PC를 오갈 때 지켜야 할 순서

지금은 양방향 동기화를 하므로 순서를 외울 필요가 없습니다. **작업 전후로 `synchere.bat`을
한 번씩 더블클릭**하면 됩니다. 자동 동기화를 켜 두었다면 그것도 대체로 알아서 합니다.

순서를 어겨도 **데이터가 사라지지 않습니다.** 양쪽이 다 바뀌었으면 어느 한쪽을 버리지 않고
**둘 다 보존**한 뒤(한쪽은 이름에 `(충돌 …)`이 붙습니다) 어느 것을 살릴지 물어봅니다.
삭제도 휴지통으로만 갑니다. 다만 충돌 사본이 쌓이면 정리가 번거로우니, 다른 PC에서
작업하기 전에 한 번 돌려 두는 편이 편합니다.

## 자주 만나는 상황

**"보류 N건 — 로컬 기준선이 없습니다"**
로컬과 원격에 같은 파일이 있는데 이 PC가 그 파일을 동기화한 적이 없을 때 나옵니다.

```bash
.\dsync reconcile -p 프로파일
```

원격 사본을 받아 내용을 대조해서, 같으면 기록만 하고(전송 없음) 다르면 알려 줍니다.
로컬 파일은 건드리지 않습니다.

**"보호(로컬 우선) N건 — 덮어쓰지 않습니다"**
그 파일을 로컬에서 고쳤다는 뜻입니다. 정상 동작입니다.
로컬 것을 올리려면 `.\dsync push`, 원격 것을 받으려면 로컬 파일을 다른 이름으로 옮긴 뒤 `.\dsync pull`.

**"unsyncable"**
Windows에 저장할 수 없는 이름(끝에 점, `CON` 같은 예약어, `<>:"|?*` 포함)이라 받지 않은 파일입니다.
Dooray 웹에서 이름을 바꾸면 다음 pull 때 받아집니다.

**업로드가 실패한 파일이 있어요**
파일 단위로 격리되므로 나머지는 정상 처리됩니다. 다시 `.\dsync push` 하면 실패한 것만 재시도합니다.
계속 실패하면 `%LOCALAPPDATA%\dooray-sync\<프로파일>\logs\dsync.log` 를 확인하세요.

## 알아둘 제약

- **삭제는 반대편에도 반영됩니다** — 단 **휴지통으로만** 갑니다(원격은 Dooray 휴지통,
  로컬은 Windows 휴지통). 영구삭제 API는 이 도구에 아예 없습니다. 한 번에 50건 이상
  또는 기준선의 20% 이상이 사라질 계획이면 **아무것도 실행하지 않고 중단**합니다.
  (2026-08-11 기본값 변경. 끄려면 `config.toml`의 해당 프로파일에서
  `propagate_deletes = false`. **이미 설치된 PC는 자기 설정을 유지합니다.**)
- 파일 1개 최대 크기는 Dooray 플랜을 따릅니다(Basic 500MB / Business 이상 10GB).
  다만 2026-08-01 실측에서 **876.7MB·589.5MB 파일이 정상 업로드**됐습니다 — 이 계정에는
  500MB 한도가 적용되지 않는 것으로 보입니다. 플랜 자체의 기관 확인은 아직 미완입니다.
- 이어올리기가 없어 큰 파일 전송이 끊기면 처음부터 다시 보냅니다.
- 같은 프로파일을 두 창에서 동시에 실행할 수 없습니다(자동으로 막힙니다). 자동 동기화를
  켜 두었다면 그 창이 마침 그 폴더를 돌고 있을 수 있습니다 — 잠시 뒤 다시 실행하면 됩니다.

## 프로그램 업데이트

### 먼저 — 프로그램 폴더 **안**의 `설치.bat`으로는 갱신되지 않습니다

`설치.bat`은 자기 옆에 `INSTALL.ps1`이 있으면 "이미 풀려 있는 폴더를 그 자리에서 점검하는
모드"로 동작합니다. 프로그램 폴더(`C:\dooraydrive`) 안의 사본이 정확히 그 경우라,
더블클릭해도 **아무것도 내려받지 않습니다.** 화면에 그렇게 적혀 나오지만, 실제로 이것을
갱신이라고 오해한 일이 두 번 있었습니다.

**갱신하려면 `INSTALL.ps1`이 없는 폴더에 `설치.bat`을 복사해 그 사본을 실행하세요.**
바탕화면이면 충분합니다. 처음 설치할 때 받아 둔 그 파일을 그대로 쓰셔도 됩니다.

### 갱신 순서

1. **자동 동기화 창을 먼저 닫습니다.** 동기화가 도는 중에 프로그램 폴더를 교체하면 그 창이
   옛 코드와 새 코드를 섞어 쓸 수 있습니다. 갱신이 끝난 뒤 다시 띄우면 됩니다(위 자동 동기화 절).
2. 바탕화면 등에 둔 `설치.bat` 사본을 더블클릭합니다.
3. 끝나면 프로그램 폴더에 `INSTALLED.txt`가 생기고, 방금 받은 버전과 시각이 적힙니다.

최신본을 새로 받아 **폴더를 통째로 교체**합니다. 받기·풀기가 성공한 뒤에만 옛 폴더를
치우므로, 네트워크가 끊겨도 지금 쓰는 사본은 그대로 남습니다(`OUT OF DATE`라고 알려 줍니다).

설정·상태·토큰은 프로그램 폴더 밖(`%APPDATA%`, `%LOCALAPPDATA%`, Windows 자격 증명 관리자)에
있어 갱신해도 유지됩니다. **동기화 폴더와 그 안의 파일은 전혀 건드리지 않습니다.**

### 특정 버전으로 되돌리기

새 버전에 문제가 있으면 버전을 지정해 과거 릴리스를 받을 수 있습니다.

```bash
설치.bat v0.2.0
```

폴더까지 지정하려면 `설치.bat D:\dooraydrive v0.2.0` 처럼 쓰면 됩니다.

**버전을 지정했는데 받지 못하면 아무것도 바꾸지 않고 멈춥니다.** "되돌리라고 했는데 옛
버전을 그대로 둔 채 성공했다고 말하는" 일이 없도록 일부러 그렇게 만들었습니다.

되돌릴 수 있는 범위는 `v0.2.0`부터입니다. 그보다 이전 버전에는 지목할 이름이 없습니다.

### "새 버전이 있습니다"가 떴을 때

동기화가 끝날 때 이런 줄이 보일 수 있습니다.

```text
새 버전이 있습니다: 0.2.0 → 0.3.0
  갱신: 프로그램 폴더 밖에 둔 설치.bat 사본을 실행하세요.
```

위 갱신 순서를 밟으시면 됩니다. **자동으로 바뀌는 일은 없습니다** — 알려 주기만 하고 실행은
사람이 합니다. 인터넷이 막혀 있으면 이 줄은 그냥 나오지 않습니다(동기화에는 영향이 없습니다).

### 하지 말아야 할 것

- **`git pull`** — `설치.bat`은 zip으로 받기 때문에 프로그램 폴더에 `.git`이 없습니다.
- **저장소를 `git clone` 해서 그 폴더를 프로그램 폴더로 쓰기** — 그렇게 하면 개발 중인
  코드가 매일 실제 파일을 동기화하게 됩니다. `설치.bat`이 이 경우를 감지하면 경고합니다.
- **파일 몇 개만 골라 복사** — 파일 사이 의존이 어긋나 프로그램이 아예 뜨지 않은 실측
  사례가 있습니다. **폴더 통째 교체가 유일한 갱신 단위입니다.**

### 문제를 알릴 때 같이 보내 주세요

프로그램이 아예 실행되지 않아도 이 둘은 확인할 수 있습니다.

- `C:\dooraydrive\INSTALLED.txt` — 어느 버전을 언제 어디서 받았는지
- `%LOCALAPPDATA%\dooray-sync\<프로파일>\logs\dsync.log` 의 **첫 줄** — 실행된 버전

프로그램이 뜨는 상태라면 `.\dsync --version` 한 줄이면 됩니다.
