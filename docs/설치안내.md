# 다른 PC에 설치하기

재택 PC·회사 PC 등 두 번째 컴퓨터에 이 도구를 설치하는 절차입니다.

> **먼저 확인**: 이 도구는 **Windows 전용**입니다. 긴 경로(`\\?\`)와 파일 잠금 처리에
> Windows API를 직접 씁니다.

## 가장 쉬운 방법 — `설치.bat` 더블클릭

아래 2~7단계를 하나로 묶은 설치 프로그램이 있습니다. **이 방법을 권합니다.**

1. [python.org](https://www.python.org/downloads/)에서 Python 설치
   (첫 화면 **`Add python.exe to PATH` 체크**)
2. 저장소를 내려받아 `C:\dooraydrive`에 두고 **`설치.bat` 더블클릭**
3. 물어보는 것은 둘뿐 — **API 토큰**(붙여넣기, 화면에 표시되지 않음)과 **파일 둘 폴더**(엔터 = `C:\Dooray`)

차단 해제 · 의존성 설치 · 토큰 등록 · 프로파일 4개 생성 · 내려받기까지 자동으로 진행되며,
작은 폴더를 먼저 받아 확인한 뒤 나머지를 받을지 물어봅니다. 중간에 끊겨도 다시 더블클릭하면
끝난 단계는 건너뜁니다.

```powershell
.\INSTALL.ps1 -Check     # 설치 전에 이 PC가 준비됐는지 점검만 (아무것도 바꾸지 않음)
.\INSTALL.ps1 -NoPull    # 설정까지만, 내려받기는 나중에
```

> `설치.bat`은 ASCII만 담고(한글은 `INSTALL.ps1`에), PowerShell을 `-ExecutionPolicy Bypass`로
> 호출한다. **zip으로 받은 파일에는 '인터넷에서 받음' 표시(MOTW)가 붙어 기본 정책(RemoteSigned)이
> `.ps1` 실행을 거부하기 때문이다** — 설치 프로그램은 시작하면서 이 표시를 먼저 해제한다.
> 아래 수동 절차를 zip으로 진행할 때는 이 문제를 직접 풀어야 한다(2단계 참고).

아래는 **수동 절차**입니다. 설치 프로그램이 막힐 때나 무엇을 하는지 확인하고 싶을 때 보세요.

## 1. Python 설치 (이미 있으면 건너뛰기)

명령 프롬프트에서 확인:

```bash
python --version
```

`3.11` 이상이 나오면 됩니다. 없거나 버전이 낮으면 [python.org](https://www.python.org/downloads/)에서 설치하되,
**설치 첫 화면의 `Add python.exe to PATH`를 반드시 체크**하세요.

## 2. 프로그램 내려받기

**방법 A — Git이 있는 경우** (업데이트가 쉬워 권장)

```bash
git clone https://github.com/martinyoo/dooraydrive.git C:\dooraydrive
```

**방법 B — Git이 없는 경우**

GitHub 저장소 페이지에서 초록색 `Code` 버튼 → `Download ZIP` → 내려받은 압축을 풀고
폴더를 `C:\dooraydrive` 로 옮깁니다.

> **zip으로 받았다면 차단을 먼저 풀어야 합니다.** 탐색기로 압축을 풀면 파일에
> '인터넷에서 받음' 표시가 붙고, 기본 실행 정책이 `.ps1` 실행을 거부합니다
> (`running scripts is disabled on this system`). PowerShell에서 한 번만:
>
> ```powershell
> Get-ChildItem C:\dooraydrive -Recurse | Unblock-File
> ```
>
> `설치.bat`을 쓰면 이 단계가 자동으로 처리되므로 신경 쓰지 않아도 됩니다.

> 이후 설명은 `C:\dooraydrive`에 두었다고 가정합니다. 다른 경로에 두었다면 그 경로로 바꿔 읽으세요.

## 3. 의존성 설치

```bash
cd C:\dooraydrive
pip install -r requirements.txt
```

## 4. API 토큰 발급·등록

토큰은 **PC마다 따로 등록**해야 합니다(설정 파일에 저장되지 않고 Windows 자격 증명 관리자에 들어갑니다).

1. Dooray 웹 접속 → 우측 상단 프로필 → **개인설정 > API > 개인 인증 토큰** → 토큰 생성
2. 명령 프롬프트에서 등록:

```bash
python -c "import keyring; keyring.set_password('dooray-sync','api-token','여기에_토큰_붙여넣기')"
```

> 기존 PC의 토큰을 그대로 써도 되고 새로 발급해도 됩니다. 토큰은 계정과 동일한 권한을
> 가지므로 메일·메신저로 보내지 마세요.

## 5. 연결 확인

```bash
cd C:\dooraydrive
.\dsync doctor
```

토큰·연결·긴 경로 지원이 `[정상]`으로 나오면 됩니다. (설정과 DB는 아직 없다고 나오는 게 정상입니다.)

## 6. 동기화 폴더 설정

### 방법 A — 스크립트 (권장, 현재 운용 중인 4개 폴더 그대로)

재택 PC에서 쓰던 프로파일 4개를 한 번에 만듭니다. 드라이브 id와 원격 경로가 이미 들어 있습니다.

```bash
.\SETUP-2ND-PC.ps1 -LocalBase "D:\Dooray"
```

`-LocalBase`는 이 PC에서 파일을 둘 최상위 폴더입니다(생략하면 `C:\Dooray`). 그 아래에
`spri 2025` / `spri 2026` / `SW통계` / `근무환경` 이 만들어집니다.

스크립트가 하는 일 — python·의존성·**디스크 여유(11.5GB)** 확인 → `doctor` → 프로파일 4개 `init`
→ 원격 스캔 완료 확인. **파일은 받지 않습니다.** 내려받기는 다음 단계에서 직접 실행합니다.

> 첫 PC용 `SETUP.ps1`과 다릅니다. 이 스크립트는 원격 폴더를 **만들지 않고**(`--create-remote` 없음),
> 기존 설정을 **덮어쓰지 않습니다**(`--force` 없음). 오타로 빈 폴더가 새로 생기면 `pull`이 0건을
> 받고도 정상처럼 보이기 때문입니다.

### 방법 B — 직접 지정

기존 PC와 **같은 원격 폴더**를 지정하되, 로컬 경로는 이 PC에 맞게 정하면 됩니다.

```bash
.\dsync init -p spri2026 --remote-path "WORK/spri 2026" --local-root "D:\Dooray\spri 2026"
```

- `-p` 는 프로파일 이름입니다. 폴더별로 하나씩 만듭니다(기존 PC와 같은 이름을 쓰면 헷갈리지 않습니다).
- `--remote-path` 는 **기존 PC와 정확히 같게** 지정해야 같은 폴더를 봅니다.
- `--local-root` 는 이 PC에서 쓸 폴더입니다. 없으면 자동으로 만듭니다.
- 드라이브를 고르라고 물으면 개인 드라이브를 선택하세요(`--drive-id`로 미리 지정해도 됩니다).

동기화할 폴더가 여러 개면 프로파일을 폴더 수만큼 만듭니다(프로파일 1개 = 폴더 1개).

```bash
.\dsync init -p 프로파일A --remote-path "WORK/폴더A" --local-root "D:\Dooray\폴더A"
.\dsync init -p 프로파일B --remote-path "WORK/폴더B" --local-root "D:\Dooray\폴더B"
```

> 원격에 아직 없는 폴더를 새로 만들면서 시작하려면 `--create-remote`를 붙입니다.
> 오타로 엉뚱한 폴더가 생기는 것을 막기 위해 기본값은 "없으면 실패"입니다.

## 7. 파일 받기

**작은 것부터 받으세요.** 경로·권한 문제가 있으면 13파일에서 드러나지, 700파일 받다가 드러나면 곤란합니다.

```bash
.\dsync pull -p swstat --dry-run    # 무엇을 받을지 먼저 확인
.\dsync pull -p swstat              # 13파일 — 여기서 정상 확인
```

정상이면 나머지를 받습니다. 2026-08-02 기준 실측값입니다.

| 순서 | 프로파일 | 파일 | 용량 |
|---|---|---|---|
| 1 | `swstat` | 13 | 0.35 GB |
| 2 | `spri2026` | 621 | 2.23 GB |
| 3 | `spri2025` | 700 | 4.13 GB |
| 4 | `workenv` | 440 | 4.53 GB |
| | **합계** | **1,774** | **11.24 GB** |

> 재택 PC가 올린 양(8.88GB)보다 큽니다. 원격에만 있고 재택 PC에는 없는 항목
> (`근무환경` 336건, `spri 2025`의 기존 업로드분)까지 함께 내려오기 때문입니다.

**중단되어도 안전합니다** — 다시 실행하면 이미 받은 것은 건너뛰고 남은 것만 받습니다.
받는 중에는 임시파일에 쓰고 검증 후 교체하므로, 끊겨도 반쪽짜리 파일이 남지 않습니다.

> **로컬에 파일이 이미 있다면** 이 순서가 아닙니다. `pull`이 전부 "보류 — 기준선 없음"으로
> 멈춥니다. 그때는 `.\dsync reconcile -p 프로파일`을 먼저 실행해 내용을 대조하세요
> (같으면 기록만 하고 전송하지 않습니다).

## 이후 사용법

| 하고 싶은 것 | 명령 |
|---|---|
| 원격의 최신 파일 받기 | `.\dsync pull -p 프로파일` |
| 내가 고친 파일 올리기 | `.\dsync push -p 프로파일` |
| 현재 상태 보기 | `.\dsync status -p 프로파일` |
| 문제 진단 | `.\dsync doctor -p 프로파일` |

**항상 `--dry-run`을 먼저 붙여 계획을 확인하는 습관을 들이세요.** 계획만 출력하고 아무것도 바꾸지 않습니다.

## 두 PC를 오갈 때 지켜야 할 순서

M1은 아직 양방향 자동 병합을 하지 않습니다. 다음 순서를 지키면 충돌이 생기지 않습니다.

1. **작업 시작 전**: `.\dsync pull` — 다른 PC에서 올린 최신본을 받습니다
2. 파일 작업
3. **작업 끝난 뒤**: `.\dsync push` — 고친 것을 올립니다

이 순서를 어겨도 **데이터가 사라지지는 않습니다**. pull은 내가 고친 로컬 파일을 절대 덮어쓰지 않고
"보호"로 건너뛰며, push는 원격을 지우지 않습니다. 다만 어느 쪽을 살릴지 직접 정해야 합니다.

## 자주 만나는 상황

**"보류 N건 — 로컬 기준선이 없습니다"**
로컬과 원격에 같은 파일이 있는데 이 PC가 그 파일을 동기화한 적이 없을 때 나옵니다.

```bash
.\dsync reconcile -p 프로파일
```

원격 사본을 받아 내용을 대조해서, 같으면 기록만 하고(전송 없음) 다르면 알려 줍니다.
로컬 파일은 건드리지 않습니다.

**"보호(로컬 우선) N건 — 덮어쓰지 않습니다"**
그 파일을 로컬에서 고쳤다는 뜻입니다. 정상 동작입니다.
로컬 것을 올리려면 `.\dsync push`, 원격 것을 받으려면 로컬 파일을 다른 이름으로 옮긴 뒤 `.\dsync pull`.

**"unsyncable"**
Windows에 저장할 수 없는 이름(끝에 점, `CON` 같은 예약어, `<>:"|?*` 포함)이라 받지 않은 파일입니다.
Dooray 웹에서 이름을 바꾸면 다음 pull 때 받아집니다.

**업로드가 실패한 파일이 있어요**
파일 단위로 격리되므로 나머지는 정상 처리됩니다. 다시 `.\dsync push` 하면 실패한 것만 재시도합니다.
계속 실패하면 `%LOCALAPPDATA%\dooray-sync\<프로파일>\logs\dsync.log` 를 확인하세요.

## 알아둘 제약

- **삭제는 전파되지 않습니다.** 어느 쪽에서 지워도 반대편은 그대로입니다(M1 안전 정책).
- 파일 1개 최대 크기는 Dooray 플랜을 따릅니다(Basic 500MB / Business 이상 10GB).
  다만 2026-08-01 실측에서 **876.7MB·589.5MB 파일이 정상 업로드**됐습니다 — 이 계정에는
  500MB 한도가 적용되지 않는 것으로 보입니다. 플랜 자체의 기관 확인은 아직 미완입니다.
- 이어올리기가 없어 큰 파일 전송이 끊기면 처음부터 다시 보냅니다.
- 같은 프로파일을 두 창에서 동시에 실행할 수 없습니다(자동으로 막힙니다).
