# dooray_sync 모듈 인터페이스 규약 (M1)

이 문서는 **병렬 구현의 단일 진실 소스**다. 각 모듈은 여기 명시된 시그니처를 정확히 따라야 하며,
의존 모듈은 여기 적힌 계약만 신뢰한다. 시그니처를 임의로 바꾸지 않는다.

- 근거: [검토보고서.md](검토보고서.md) §3(실측), [구현계획서.md](구현계획서.md) §4(강제 규칙)
- 언어/환경: Python 3.11+, Windows 11, 콘솔 cp949
- 코드 스타일: 기존 `poc/poc_common.py`와 동일 — 한국어 주석, `from __future__ import annotations`

## 0. 공통 규칙 (전 모듈 필수)

1. **인코딩**: 진입점(`cli/main.py`)에서 `sys.stdout/stderr.reconfigure(encoding="utf-8", errors="replace")`.
   모든 파일 IO는 `encoding="utf-8"` 명시. 로깅 `FileHandler(..., encoding="utf-8")`.
2. **경로**: 로컬 파일시스템 접근은 **반드시** `util.paths.ext_path()`를 거친다(`\\?\` 접두).
   `open()`, `os.stat()`, `os.replace()`, `os.listdir()`, `os.makedirs()` 전부 해당.
3. **예외**: API 실패는 `api.client.DoorayApiError`, 로컬 안전 위반은 각 모듈 정의 예외.
   예외 메시지에 토큰이 들어가지 않도록 주의.
4. **영구삭제 금지**: `DELETE /drive/v1/drives/{d}/files/{f}` 호출 코드를 어디에도 작성하지 않는다.
5. 타입 힌트를 붙이되 런타임 의존(pydantic 등)은 쓰지 않는다. `dataclasses` 사용.

## 7. `dooray_sync/api/client.py`

```python
class DoorayApiError(RuntimeError):
    def __init__(self, message, *, status=None, result_code=None,
                 result_message=None, path=None)
    status: int | None
    result_code: int | None
    result_message: str | None
    path: str | None

class DoorayClient:
    """실측 강제 규칙 A1~A4의 단일 관문.

    A1: 모든 응답에서 header.isSuccessful / resultCode 검사.
        **HTTP 200이어도 실패일 수 있다** (실측: resultCode=-15700100 "No access authority").
    A2: raw 전송의 307을 수동 추적하고 재요청에 Authorization을 재부착
        (무인증 재요청은 401 — 실측). 업로드는 multipart를 재구성(파일 재오픈).
    A3: rate-limit 헤더 기반 선제 감속. X-RateLimit-Remaining < LOW_WATERMARK면
        1/replenish_rate 만큼 대기. 429는 Retry-After 우선 지수 백오프.
        **파일 객체 업로드는 자동 재시도 금지**(스트림 소진).
    A4: 타임아웃 connect 10 / read 600 / write 1800.
    """
    LOW_WATERMARK = 5

    def __init__(self, base_url: str, token: str, *, logger: logging.Logger | None = None)
    def close(self) -> None
    def __enter__ / __exit__

    # 관측값 (doctor 명령에서 사용)
    last_rate_limit: dict[str, str | None]   # remaining/burst/replenish/requested

    def request(self, method: str, url: str, *, retry: bool = True,
                label: str = "", **kw) -> httpx.Response
        """url이 절대면 그대로, 아니면 base_url + path.
        follow_redirects=False 고정. 429/5xx 백오프(retry=True일 때만)."""

    def api(self, method: str, path: str, **kw) -> dict
        """envelope 검사(A1) 후 body dict 반환. 실패 시 DoorayApiError."""

    def download_to(self, path: str, dest_tmp: Path) -> dict
        """?media=raw GET. 307 수동 추적(A2) + 스트리밍으로 dest_tmp에 기록.
        반환: {'bytes': int, 'md5': str, 'content_length': int|None,
               'redirect_host': str|None}
        ※ 원자적 교체(os.replace)는 호출측(DriveAPI.download) 책임."""

    def upload_file(self, method: str, path: str, filename: str,
                    local_path: Path) -> dict
        """multipart 업로드(POST 신규 / PUT 새 버전). 307 시 파일을 재오픈해
        multipart 재구성(A2). retry=False 고정(A3). envelope 검사 후 body 반환."""
```

## 11. `dooray_sync/cli/main.py`

```
dsync init      # 토큰 확인 → 드라이브 선택 → 로컬 루트 지정 → 설정/DB 생성
                #   → 원격 전체 순회(목록 API)로 files 테이블 구축
                #   → changes 커서를 live tip으로 전진(과거 이력 재생 안 함)
dsync status    # 설정/DB 요약, sync_status별 건수, 커서, 마지막 동기화 시각
dsync push      # 로컬 → 원격 단방향. 원격의 어떤 것도 삭제하지 않음.
                #   신규는 POST, 기존은 (변경 시) PUT 새 버전. 409는 재조회 후 재판정.
                #   서버 저장명을 DB의 server_name에 정본 기록(R14).
dsync pull      # 원격 → 로컬 단방향. **로컬이 수정된 파일은 절대 덮어쓰지 않고 skip + 경고.**
                #   원자적 다운로드(C1) + 교체 직전 재-stat(C2).
dsync doctor    # 토큰/연결/TLS/rate-limit 헤더/긴 경로/DB 무결성 점검
```

- 전 명령 `--profile NAME`, `--dry-run` 지원. `push/pull`은 dry-run 시 Action 표만 출력.
- 단일 인스턴스 잠금은 `init`을 제외한 모든 상태 변경 명령에 적용.
- 진행 상황은 표준 출력에 간결하게. 상세는 `state_dir/logs/dsync.log`(UTF-8).
- 예외는 사용자 친화 메시지 + 종료코드(0 성공 / 1 실패 / 2 설정·토큰 문제 / 3 잠금).

## 12. 금지 사항 (구현 시 절대 하지 말 것)

1. `len(items) < size`로 changes 페이징을 종료하지 말 것 (R11 — 무성 데이터 누락)
2. HTTP 상태코드만으로 성공 판정하지 말 것 (R15 — 200+음수 resultCode)
3. 영구삭제 API를 호출하는 코드를 작성하지 말 것
4. `\\?\` 접두 없이 로컬 파일을 열지 말 것
5. 토큰을 로그·설정파일·예외 메시지에 평문으로 남기지 말 것
6. 수정된 로컬 파일을 검증 없이 덮어쓰지 말 것 (C2 재-stat 필수)
7. 업로드 시 로컬 파일명을 그대로 DB에 정본으로 기록하지 말 것 (R14 — 서버 저장명 사용)
