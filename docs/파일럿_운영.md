# 2주 파일럿 운영 가이드

M1(수동 동기화)을 실제 업무 파일로 2주간 검증하는 절차입니다.

## 대상 (설정 완료됨)

| 프로파일 | 로컬 폴더 | 원격 폴더 | 규모 |
|---|---|---|---|
| `spri2025` | `...\WORK\spri 2025` | `WORK/spri 2025` (신규) | 700파일 / 4.2GB |
| `spri2026` | `...\WORK\spri 2026` | `WORK/spri 2026` (신규) | 623파일 / 2.3GB |
| `swstat` | `...\WORK\SW통계` | `WORK/SW통계` (기존 7건) | 13파일 / 359MB |
| `workenv` | `...\WORK\근무환경` | `근무환경` (기존 422건) | 104파일 / 3.6GB |

로컬 원본은 Google Drive 동기화 폴더 안에 있습니다. **파일럿 기간에는 원본을 지우지 마세요** —
Dooray 쪽은 사본으로만 취급합니다.

## 시작 절차 (1회)

**PowerShell 주의**: 보안상 현재 폴더의 명령을 자동으로 찾지 않으므로 앞에 `.\`를 붙여야 합니다.

```bash
cd C:\drive\dev\dooraydrive
```

`.\` 없이 어디서나 쓰고 싶으면 PATH에 한 번만 등록하세요(등록 후 PowerShell 창을 새로 열어야 적용됩니다).

```bash
[Environment]::SetEnvironmentVariable('PATH', [Environment]::GetEnvironmentVariable('PATH','User') + ';C:\drive\dev\dooraydrive', 'User')
```

### 1단계 — 계획 확인

```bash
.\dsync push -p spri2025 --dry-run
```

무엇이 올라갈지 표로 나옵니다. 예상과 다르면 여기서 멈추세요.

### 2단계 — 첫 업로드

용량이 크므로 **한 번에 하나씩**, 시간 여유가 있을 때 실행하세요.

```bash
.\dsync push -p spri2025
.\dsync push -p spri2026
.\dsync push -p swstat
.\dsync push -p workenv
```

예상 소요: 전체 약 10.5GB, 업로드 속도 약 3.7MB/s 기준 **1.5~2시간**. 중간에 끊겨도
다시 실행하면 못 올린 것만 이어서 올립니다.

### 3단계 — 결과 확인

```bash
.\dsync status -p spri2025
```

`sync_status`에 `error`가 있으면 로그를 봅니다:
`%LOCALAPPDATA%\dooray-sync\<프로파일>\logs\dsync.log`

## 매일 사용

> **2026-08-07 전환**: 일상 운용이 M1 push 단방향에서 **M2 양방향 sync**로 바뀌었습니다.
> sync 대상은 `spri2025`·`spri2026`·`swstat` 3개입니다. `workenv`는 push 전용
> (원격 전용 336건/약 1GB를 받지 않기로 결정), `study`·`writing`은 sync 미전환입니다.

### 방법 1 — 폴더 안 `synchere.bat` 더블클릭 (가장 간단)

동기화 대상 폴더(그리고 최상위 `WORK`)에 `synchere.bat`이 들어 있습니다.
**더블클릭하면 그 폴더가 양방향 동기화됩니다** — 올리기와 받기를 한 번에,
계획을 출력하면서 진행합니다.

- **모든 사본이 동일한 파일입니다.** 아무 폴더에나 복사해 두면 동작합니다:
  - 동기화 폴더(또는 그 하위 어디든)에서 실행 → 위로 올라가며 **품는 동기화 폴더**를 찾아 그것을 동기화
  - `WORK`처럼 여러 동기화 폴더를 거느린 상위 폴더에서 실행 → **아래의 대상 전부**를 차례로 동기화
- **이 파일 자신은 절대 동기화되지 않습니다**(양방향 모두 상시 제외). 새 폴더에 쓰려면
  직접 복사해 두세요. Dooray 웹에도 올라가지 않습니다.
- 삭제는 전파하지 않고 보고만 합니다. 충돌은 양쪽 내용을 모두 보존합니다.
- 계획만 보려면: 그 폴더에서 `cmd` 열고 `synchere.bat --dry-run`
- sync 제외 폴더(근무환경 등)에서 실행하면 실행하지 않고 사유를 안내합니다.
  `WORK`에서 실행할 때도 제외 대상은 사유를 표시하고 건너뜁니다.
- **이 파일이 곧 등록/해제 스위치입니다** (2026-08-07):
  - 아직 등록 안 된 폴더에 복사해 실행하면 **자동 등록** 후 바로 동기화됩니다
    (같은 부모 아래 등록된 형제 폴더가 있을 때 — 예: `WORK` 아래 새 폴더).
  - 동기화 폴더 루트에서 이 파일을 **지우면**, 다음 실행(synchere 또는
    `SYNC.ps1 -Sync`) 때 그 폴더가 동기화 대상에서 **자동 해제**됩니다.
    기록은 남으므로 파일을 다시 복사해 실행하면 **그대로 재등록**됩니다.
  - 근무환경(push 전용) 같은 수동 결정 폴더는 이 규칙으로 바뀌지 않습니다.

### 방법 2 — 전체 한 번에

```bash
.\SYNC.ps1 -Sync
```

계획을 먼저 보여주고 확인받은 뒤 실행합니다. 제외 프로파일(workenv·study·writing)은
사유를 표시하고 자동으로 건너뜁니다 — `-Only`로 지정해도 제외는 우회되지 않습니다
(정책 정본은 config의 `sync_mode`이고, 우회해도 CLI 게이트가 거부합니다. 전환은
`python tools\set_sync_mode.py <프로파일> sync`).

| 하고 싶은 것 | 명령 |
|---|---|
| **전체 양방향 동기화 (권장)** | `.\SYNC.ps1 -Sync` |
| 계획만 보기 | `.\SYNC.ps1 -Sync -DryRun` |
| 전체 올리기만 | `.\SYNC.ps1` |
| 전체 받기만 | `.\SYNC.ps1 -Pull` |
| 확인 없이 바로 | `.\SYNC.ps1 -Sync -Yes` |
| 전체 상태 요약 (마지막 sync 시각 포함) | `.\SYNC.ps1 -Status` |
| 일부만 | `.\SYNC.ps1 -Sync -Only spri2026,swstat` |

프로파일 목록은 `config.toml`에서 직접 읽으므로, **폴더를 추가해도 스크립트를 고칠 필요가 없습니다.**
한 프로파일이 실패해도 나머지는 계속 진행하고 마지막에 실패 목록을 알려 줍니다.

### 개별로 하고 싶으면

- **한 폴더만 양방향** → `.\dsync sync -p 프로파일` (계획 먼저: `--dry-run`)
- **올리기만** → `.\dsync push -p 프로파일` / **받기만** → `.\dsync pull -p 프로파일`

주 1~2회 `.\SYNC.ps1 -Status`로 상태만 확인하면 충분합니다.

2주 동안 아래를 지켜봐 주세요. 이게 M2 설계의 근거가 됩니다.

| 항목 | 확인 방법 |
|---|---|
| 데이터 유실 0건 | 로컬 원본과 Dooray 웹에서 파일 개수·크기 대조 |
| 실패한 파일 | `.\dsync status`의 `error` 건수, 반복 실패 여부 |
| 589MB 동영상 업로드 | `spri 2026\과기정통부 보고\26.1 정통실 회의\video1203881183.mp4` — 플랜 한도 초과 시 실패 |

| 이름 문제 | `unsyncable` 건수 |

## 문제가 생기면

**"보류 N건 — 로컬 기준선이 없습니다"**
```bash
.\dsync reconcile -p 프로파일
```
원격 사본을 받아 내용을 대조합니다. 같으면 기록만 하고(전송 없음), 다르면 알려 줍니다.
로컬 파일은 건드리지 않습니다.

**"보호(로컬 우선) N건"**
그 파일을 로컬에서 고쳤다는 뜻입니다. 정상 동작입니다.
로컬 것을 올리려면 `push`, 원격 것을 받으려면 로컬 파일을 다른 이름으로 옮긴 뒤 `pull`.

**"충돌보존 / 충돌 사본 N건"** (sync)
같은 파일이 양쪽에서 다르게 수정된 경우입니다. **어느 쪽도 잃지 않습니다** —
원래 이름에는 원격본이, `파일명 (충돌 날짜 시각)` 사본에는 내 편집본이 남습니다.
```bash
.\dsync resolve -p 프로파일 --list        # 목록 확인
.\dsync resolve -p 프로파일 --id N --keep local|remote|both
```

**"실제로 사라질 항목 N건" (0이 아님)**
삭제 전파가 꺼진 상태에서는 나올 수 없는 값입니다. **실행하지 말고 멈춘 뒤**
`.\dsync sync -p 프로파일 --full --dry-run`으로 원인을 확인하세요.
(SYNC.ps1 -Sync는 이 경우 해당 프로파일을 자동으로 실행에서 제외합니다.)

**업로드 실패**
파일 단위로 격리되므로 나머지는 정상 처리됩니다. `.\dsync push`를 다시 실행하면 실패한 것만 재시도합니다.

**뭔가 이상하다 싶으면**
```bash
.\dsync doctor -p 프로파일
```
그리고 **일단 멈추고** 로그를 확인하세요. 억지로 진행하지 마세요.

## 안전 보장 (파일럿이 안전한 이유)

- **삭제가 전파되지 않습니다** — 어느 쪽에서 지워도 반대편은 그대로입니다
- **수정된 로컬 파일을 덮어쓰지 않습니다** — 다운로드 직전에 다시 확인하고, 바뀌었으면 받은 내용을 버립니다
- **원격을 삭제·이동하지 않습니다** — `push`는 추가와 새 버전만 만듭니다
- **영구삭제 API가 코드에 아예 없습니다**
- 다운로드는 임시파일에 받아 검증 후 교체하므로, 중단되어도 기존 파일이 손상되지 않습니다

## 2주 뒤

파일럿 결과(유실 0건, 실패 건수, 불편했던 점)를 정리하면 M2(양방향 동기화·충돌 사본 생성)와
M3(자동 동기화) 설계에 반영합니다.
